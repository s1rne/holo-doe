# Синтез ДОЭ под одну сцену: рецепт и потолок качества

Документ отвечает на три вопроса: какая параметризация фазы и какая потеря дают максимум метрик
при оптимизации под конкретную четвёрку изображений, какой рецепт лучший по качеству и времени,
и чем качество ограничено в принципе.

Все числа получены через `holo.evaluate.evaluate`: фаза сохраняется в 8-битный PNG, восстановление
считается из этого PNG как амплитуда |K|, нормируется по максимуму и округляется до 8 бит,
метрики — коэффициент Пирсона и `skimage` SSIM. Железо: Apple M4 Max, PyTorch MPS, float32.

Воспроизведение:

```bash
PYTHONPATH=. uv run python scripts/per_instance.py data/targets/photos data/targets/glyphs data/targets/extra
PYTHONPATH=. uv run python scripts/analysis.py data/targets/photos data/targets/glyphs data/targets/extra
```

## Наборы

| набор | что это |
|---|---|
| photos | полутоновые фотографии skimage: camera, astronaut, coffee, coins |
| glyphs | бинарные символы Л, А, З, Р |
| extra | другой источник и другая статистика: chelsea, rocket, moon, cell |

## Что оказалось важным

**Считать потерю ровно по проверке.** `holo/objective.py` повторяет путь проверки целиком:
запись фазы в 8-битный код и обратно, восстановление по амплитуде, нормировка по максимуму,
округление до 8 бит, затем CC и SSIM. Оба округления пропускают градиент через straight-through
estimator. Замена `image_loss` на эту потерю даёт основной отрыв от эталона при тех же шагах.

**Мягкий максимум в нормировке не нужен.** Нормировка делит на максимум, и градиент по нему
достаётся единственному пикселю. Вариант, где тот же максимум считается как степенное среднее
(mean x^p)^(1/p) с p = 16, а значение подменяется настоящим максимумом (`Objective.peak_power`),
при сравнении по интенсивности давал заметный плюс, а при сравнении по амплитуде проигрывает
обычному максимуму на всех трёх наборах (photos 1,018 против 1,025). В рецепте он выключен.

**Гладкая фаза в плоскостях восстановления против спекла.** Метрики считаются по амплитуде |K|,
а не по интенсивности, и это главное отличие задачи от привычной постановки: спекл в тёмных
местах даёт амплитуду порядка корня из интенсивности, фон после нормировки не округляется в ноль
и SSIM рушится. Спекл возникает, когда фаза в плоскости восстановления случайна. Поэтому первый
этап (`holo/pretrain.py`) подгоняет ДОЭ под комплексную цель A·exp(jφ), где φ — свободная фаза
низкого разрешения 4×4 с бикубической интерполяцией. Решение выходит с малым спеклом, второй
этап (градиентный спуск по точной потере) его дотягивает. На бинарных символах это даёт SSIM
около 0,63 вместо 0,10 при случайной инициализации.

**Яркий пик как рычаг SSIM.** Тот же эффект достигается иначе: если выгнать часть энергии в один
яркий пик, нормировка по максимуму опускает фон ниже половины младшего разряда и он округляется
ровно в ноль. Штраф за среднюю яркость (`Objective.dim_weight`) делает это явно. На символах
рычаг работает (SSIM с 0,10 до 0,61 при падении CC с 0,81 до 0,67), на фотографиях вредит: у них
нет истинно чёрного фона, и затемнение съедает градации.

**Инициализация решает, в какой бассейн попадёт решение.** На бинарных символах случайная фаза
ведёт в решение с CC 0,81 и SSIM 0,10, а инициализация из 50 итераций GS или из этапа гладкой
фазы — в решение с CC 0,70 и SSIM 0,63. Сумма метрик во втором случае заметно выше, но если
смотреть только на CC, выгоден первый вариант. Поэтому рецепт считает оба прогона и выбирает
по той же потере, а не по типу изображений.

**Неявные представления фазы работают как слабый вариант того же приёма.** SIREN и MLP на
фурье-признаках задают гладкую фазу ДОЭ, и на наборе extra это даёт SSIM 0,57 и 0,55 против
0,46 у свободной фазы, но CC падает с 0,52 до 0,41. По сумме они не выигрывают, зато
подтверждают, что рычагом служит гладкость, а не ёмкость сети.

## Что не сработало

- Нейросетевые параметризации фазы (deep image prior на U-Net, SIREN, MLP на фурье-признаках)
  при равном числе шагов проигрывают свободной фазе по сумме метрик и стоят в 3–13 раз дороже
  по времени: оптимум фазы шумоподобный, и ёмкость сети на него не ложится.
- Перепараметризация фазы углом свободного комплексного поля (`ComplexField`) выигрыша не даёт.
- Рестарты: восемь параллельных стартов за то же суммарное время хуже одного длинного прогона.
- Больше шагов: после 3000 прирост в третьем знаке, после 10000 его нет.
- Штраф за пик-фактор (отношение максимума к среднему, обратный `dim_weight`) ухудшает обе метрики.
- Квантование фазы через STE: на итог влияет в четвёртом знаке. 8 бит фазы — не ограничение.
- Мягкий минимум по плоскостям (`softmin`) выравнивает качество между изображениями, но сумма
  метрик падает: выравнивание идёт вниз, к худшей плоскости.

## Потолок

Три независимые оценки сверху, все считает `scripts/analysis.py`.

**Четыре отдельных ДОЭ, по одному на изображение.** Для полутоновых наборов CC 0,996–0,999 и
SSIM 0,98–0,99: ни фазовый характер ДОЭ, ни 8 бит квантования, ни размер 128×128 не ограничивают,
ограничение создаёт требование восстановить четыре изображения из одного элемента. Для бинарных
символов та же проверка даёт CC 0,964, но SSIM всего 0,33 — при случайном старте спекл на чёрном
фоне остаётся даже с одной плоскостью. Рецепт с этапом гладкой фазы получает на четырёх
плоскостях SSIM 0,63, то есть по SSIM на бинарных изображениях ограничивает не крослток, а
спекл-структура решения.

**Связь плоскостей.** Поля в двух плоскостях связаны свёрткой с ядром FFT(c_j/c_i), где c_z —
квадратичный множитель. Полуширина ядра между соседними плоскостями 2,5–3 пикселя, между
крайними 8,3 пикселя; 90 % энергии ядра лежит в радиусе 3–8 пикселей. Детали мельче этого
масштаба у плоскостей могут быть разными, а распределение энергии на более крупных масштабах
общее для всех четырёх. Оракул, в котором низкие частоты принудительно общие (среднее по четырём
целям), а высокие свои, даёт для photos CC 0,70 при σ = 2 и 0,80 при σ = 4. Это порядок потолка
для четырёх независимых изображений в одном фазовом ДОЭ.

**Счёт степеней свободы.** ДОЭ даёт 128² = 16384 вещественных параметра. Четыре изображения
требуют 4 × 16384 ограничений на амплитуду, и только четыре из них снимаются свободой масштаба.
Поля в плоскостях 2–4 полностью определяются полем в плоскости 1, так что свобода фазы в
плоскостях восстановления степеней свободы не добавляет. Система переопределена вчетверо — отсюда
CC около 0,6 на фотографиях.

Практический вывод: зазор между достигнутым (CC ≈ 0,60 на photos) и оракулом общих низких частот
(CC ≈ 0,70–0,80) — это спекл фазового решения, а не крослток. Уменьшать его нужно средствами,
которые управляют фазой в плоскостях восстановления; этап гладкой фазы — первый шаг в эту сторону,
и на бинарных изображениях он даёт самый большой прирост.

## Лучший рецепт

**Качество.** Два прогона и выбор лучшего по той же потере (`best_of_both` в
`scripts/per_instance.py`):

1. случайная фаза → 3000 шагов Adam по точной потере, шаг 0,3 с косинусным спадом,
   STE-квантование включается со второй половины шагов;
2. этап гладкой фазы (3000 шагов, разрешение фазы 4×4) → 3000 шагов Adam, шаг 0,1, та же потеря.

Выбор по потере, а не по типу изображений: на полутоновых выигрывает первый прогон, на бинарных
второй. Итог: photos CC 0,604 / SSIM 0,421; glyphs CC 0,699 / SSIM 0,626; extra CC 0,523 /
SSIM 0,459. Время 10–13 с на сцену (Apple M4 Max, MPS). Против эталонов это +0,032 суммы метрик
на photos, +0,065 на glyphs, +0,020 на extra при вчетверо меньшем времени.

**Скорость.** Обучаемый оптимизатор: 16 шагов сети (`runs/learned_optimizer.pt`, обучение
500 итераций ≈ 5 мин на случайных сценах) плюс 500 шагов обычного спуска — 0,7 с на сцену и
97–98 % суммы метрик лучшего рецепта (photos 1,001 против 1,025; glyphs 1,283 против 1,324).
Один прогон сети без дообучения даёт 0,03 с и около 85 % суммы — это и есть нейросетевой
«мгновенный» режим.

**Устойчивость к определению восстановления.** Все числа в колонках «CC |K|²» и «SSIM |K|²»
показывают, что решение, оптимизированное под амплитуду, при пересчёте по интенсивности теряет
SSIM (например, photos 0,421 → 0,259). Оптимизация сразу по обоим определениям («|K| и |K|²»)
даёт компромисс: photos 0,581 / 0,401 по амплитуде и 0,547 / 0,349 по интенсивности. Если
определение проверки не зафиксировано, брать этот вариант; при известном амплитудном —
основной рецепт.
